PDF IMPORT RESCUE — 2026-08-25

Observed regression
- Valid Authority timetable PDFs started failing before row extraction with PDF_HEADER_UNRESOLVED.
- Earlier failures could also expose a very long numeric/raw OCR string as the supposed college identity.

Root causes fixed
1) Invisible RTL/Bidi control marks inserted by OCR/PDF engines sat between Arabic header labels and their numbers. Regexes such as «الكلية 01» then failed despite the text being visibly correct.
2) First-page scan preflight OCR read only the top 24% of the rotated page. Some phone/cropped exports place the college/branch/department block below that band.
3) The importer required a separately OCRed parent-college line even when the explicit branch line already stated the same college family (for example «كلية التربية الأساسية بنات»).
4) Department-code OCR noise could duplicate a neighbouring digit (for example 0101 -> 020101) and overrule a unique, correct Arabic department name.
5) Scan completeness threshold had been tightened from 55% to 70%, rejecting usable photographed ruled tables.
6) Raw header-name OCR could carry timetable digits into the user-facing mismatch message.

Implemented
- Strip Unicode bidi controls before all numeric/header matching.
- Reconstruct first-page embedded PDF text by physical coordinates in addition to the flat token stream.
- Expand first-page OCR header band to 42% and upscale that bounded band 2x.
- Sanitize header identity names to Arabic name text only, capped to a safe length.
- Accept the explicit branch college-family wording as evidence for the parent college when the tiny parent-college cell alone is missed.
- Let a unique department-name match override a noisy OCR department-code cell; a real uniquely named different department still blocks.
- Restore the 55% photographed-grid rescue threshold while keeping downstream structural/course/location validation as the publish safety gate.
- Kept the signed PDF import receipt and strict term/branch/department mismatch protection.
