# رفع Patch المباني والقاعات إلى AI Studio

هذه الحزمة **Patch فقط** وليست المشروع الكامل. لا يوجد داخلها Backup قاعدة البيانات.

## طريقة الاستخدام

1. افتح نفس مشروع SCHEDULE الحالي في AI Studio.
2. ارفع محتويات ZIP مع الحفاظ على المسارات كما هي (`src/...`, `server.ts`, `package.json`...).
3. لا تستبدل إعدادات Firebase/Firestore أو مشروع Firebase الحالي بقاعدة جديدة.
4. نفّذ تثبيت Dependencies في بيئة AI Studio/النشر (`npm ci` أو ما يستخدمه المشروع هناك).
5. شغّل `npm run test` ثم `npm run lint` ثم `npm run build` في البيئة التي لديها اتصال npm كامل.
6. انشر **الكود فقط** على نفس مشروع الإنتاج المرتبط بFirestore الحالية.
7. سجّل دخول Super Admin وافتح «المباني والقاعات».
8. شغّل **Preview** للمهاجرة أولًا. لا تنفذ Apply قبل مراجعة الأرقام.
9. عند الاعتماد، شغّل «تهيئة سجل المباني والقاعات». العملية مصممة لتكون Idempotent وتحتفظ بسجل Old/New وMigration ID ويمكن Rollback.
10. الحالات غير المحسومة لا تُحوّل تلقائيًا؛ راجع `ROOMS_REVIEW.md` أو `room-registry-review.xlsx`.

## مهم

- `012B07` يعني: Prefix الكلية/الموقع `012B` + **المبنى 07**. القاعات تأتي تحته ككيانات مستقلة.
- لا ترفع ملف النسخة الاحتياطية الحقيقي إلى Frontend أو Git أو AI Studio كـasset.
- `PENDING_ROOM` ليس Room ولا يدخل في إحصاءات القاعات.
- المباني/القاعات `PROBABLE` مولدة بحالة غير فعالة إلى أن يعتمدها Admin.

## قاعدة البيانات الحالية

الكود يستخدم Firestore كقاعدة منفصلة عن ملفات Frontend/Release. لذلك الحزمة لا تحتاج نسخة Backup لكي تعمل Runtime. الـBackup استُخدمت هنا فقط لاستخراج Seed آمن ومجمّع. المهاجرة التاريخية المقترحة تعمل داخل النظام على قاعدة Firestore الحالية بعد Preview وإجراء Admin صريح.

## ملاحظة الاختبار

اختبارات Registry وGuide نجحت في بيئة التنفيذ الحالية، لكن Build الكامل لم يمكن إكماله هنا لأن dependencies غير مكتملة وبيئة التنفيذ لم تستطع تنزيل الحزمة الناقصة من npm. لذلك يجب تشغيل `npm ci && npm test && npm run lint && npm run build` داخل AI Studio/بيئة النشر قبل اعتماد Release الإنتاجي.
