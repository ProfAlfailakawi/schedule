تحديث الجدول الأكاديمي — طريقة الرفع
=====================================

مهم: تُفَك هذه الحزمة **فوق** مجلد المشروع (دمج)، لا كاستبدال كامل للمساحة.

خطوات الرفع
-----------
1. فك الضغط فوق مجلد المشروع مباشرة (نفس المسارات، بدون مجلد إضافي).
2. لا تحذف هذه المجلدات إن كانت موجودة عندك:
      database/     ← نسخة البيانات (db.json.gz)
      node_modules/ ← يُعاد بناؤه عند النشر
      dist/         ← يُعاد بناؤه عند النشر
      tests/  scripts/  docs/  .github/
3. ارفع كالمعتاد إلى AI Studio / Cloud Run.
4. تأكد أن NODE_ENV=production في بيئة التشغيل.


الشاشة البيضاء — تم علاجها من جذرها
------------------------------------
كان الخادم يردّ على أي ملف مفقود بصفحة index.html وبحالة 200. النتيجة: متصفح
ما زال يحمل نسخة الإصدار السابق يطلب ملف JavaScript قديم، فيستلم HTML، ويحاول
تشغيله كبرنامج، فتبقى الصفحة بيضاء بلا أي خطأ ظاهر في سجل الشبكة.

ما تغيّر:
  • الملف المفقود صار يردّ 404 صادقة بدل صفحة التطبيق.
  • داخل index.html نفسه حارس إقلاع: إذا لم تظهر الشاشة، يمسح الذاكرة المؤقتة
    ويلغي تسجيل Service Worker ويعيد التحميل مرة واحدة. ولو فشل مجدداً يعرض
    رسالة عربية وزر إعادة محاولة — لا شاشة بيضاء بعد اليوم.
  • Service Worker لم يعد يخزّن الصفحة نفسها (كان هذا سبب تعلّق الإصدار القديم).
  • أي خطأ في العرض داخل React يعرض بطاقة مقروءة بدل شاشة فارغة.


ملف src/styles/refinement.css
------------------------------
أعاده AI Studio لأن حذفه يكسر البناء إن بقي أي استيراد له. الحل في هذه الحزمة:
الملف **موجود وفارغ تماماً** (تعليق فقط). أي استيراد له ينجح ولا يضيف قاعدة
واحدة، ولا يتغلب على التصميم كما كان يفعل سابقاً. لا تحذفه ولا تكتب فيه.


فحوصات نُفِّذت قبل التسليم
-------------------------
  npm run lint                → بدون أخطاء
  npx tsx tests/run-tests.ts  → 2004 اختبار ناجح · 0 فاشل
  npm run build               → ناجح (vite + esbuild)
  تشغيل dist/server.cjs بـ NODE_ENV=production:
      كل الصفحات 200 · الملف المفقود 404 · حارس الإقلاع موجود في الصفحة المخدومة

البيانات الحقيقية فقط
---------------------
الوضع الافتراضي الآن هو بيانات الجامعة (Firestore). اترك DATA_MODE محذوفاً أو
اضبطه على firestore. إذا تعذر الاتصال بقاعدة البيانات:
  • على Cloud Run: لا تبدأ النسخة الجديدة إطلاقاً، فتبقى النسخة السابقة تعمل.
  • محلياً: يبقى الخادم ويردّ 503 مع سبب الفشل بدل عرض بيانات وهمية.
لن يعمل البرنامج بعد اليوم على بيانات تجريبية إلا إذا كتبت DATA_MODE=demo بنفسك،
وعندها يظهر تحذير واضح في السجل عند كل تشغيل.
تأكد في بيئة التشغيل من: FIREBASE_PROJECT_ID و FIREBASE_DATABASE_ID.
