SCHEDULE — Location Registry Patch
Generated: 2026-08-24

ROOT CAUSE
- Building and room identity was stored/compared in several paths as raw AdRoomCode/AdRoomHall strings.
- That allowed aliases such as B9 / B09 / 9 / 012B09 to behave as separate locations.
- Some OCR/copy/intelligence/Hall Barter flows could reintroduce raw location strings.
- There was no authoritative central building/room registry with backend enforcement.

FIX
- Master Building/Room Registry with stable IDs, aliases, confidence/evidence and historical review queue.
- Authoritative college/site prefixes supplied by the system owner; e.g. 012B + building 7 = 012B07.
- Runtime uses canonical buildingId/roomId; rooms are scoped to a building.
- PENDING_ROOM is a system state, not a room.
- Admin-only building/room mutation enforced on backend.
- Conservative, idempotent and reversible historical migration with preview + rollback records.
- Import/copy/edit/intelligence/Hall Barter/conflicts/reports use the registry/preflight path.
